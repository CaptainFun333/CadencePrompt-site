Sending a script in more than one language

Three ways that work, and three rules for all of them.

When a show runs in more than one language, Cadence reads each language as a script of its own, kept in step line for line. The easier the file is to read, the less anyone has to prepare by hand. Here is what works best, in order.

The three rules

  • The same cue numbers in every language ([001], [002], and so on).
  • The same number of lines in every language, in the same order. If one language really has an extra announcement, that is fine: Cadence says so plainly and carries on.
  • Say which language is which: in the file name, in a heading row, or in a heading.

1. One file for each language (best)

Send Summit_EN.docx, Summit_ES.docx, and so on, with the same cue numbers in each. Nothing special is needed on our side: each file is a normal import. Sample, English · Sample, Spanish

2. One table, a column for each language

A heading row that names each language (English, Español), and one row for each beat. Put the speaker and the cue number in their own column ([001] HOST). A column of visuals or notes on the left is fine, and a row across the whole table can carry a scene title. Please do not merge the language cells. Sample table

3. One file, a section for each language

Put each language under its own heading on a line of its own, such as ENGLISH (EN) and ESPAÑOL (ES) (Heading 1 is best). Anything before the first heading, like the title, goes into every language. Repeat the same cue numbers in each section. Sample sections

Anything else

Send it as it is and tell us which language you need. Cadence can still import it, but someone has to prepare it by hand.

Please avoid

Facing pages (one language on the left page, one on the right), translations hidden in footnotes or comments, and languages switched off through Word styles. They are hard to read without guessing. Any of the three ways above is easy to send instead.
